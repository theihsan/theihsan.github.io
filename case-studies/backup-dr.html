NAS Backup & Disaster Recovery

Ultraction General Contracting LLC · Abu Dhabi, UAE · Infrastructure & Resilience
01 — Context & Problem
Backup coverage needed a meaningfully faster recovery path

The organization needed resilient backup coverage with a materially lower recovery time than the existing approach allowed. Alongside this, a live shared-storage access fault needed resolving — a shared folder was reachable at its top level but denied specific users access to particular subfolders.

02 — Environment
Synology NAS platform, local and cloud replication

A Synology NAS platform serving as the organization's primary backup target, configured with both local and cloud replication across the multi-site operation. The same platform also hosts a virtual machine used for an internal service.

03 — My Responsibility
End-to-end ownership of the backup platform

Designed and implemented the backup architecture, and own the NAS platform end-to-end — including the permissions structure, replication configuration, and the hosted VM's exposure model.

04 — Investigation
Access worked at the top level, broke on subfolders

Users could reach a shared folder's top level without issue, but access was denied on specific subfolders for the same users — a pattern that pointed toward a permissions-inheritance problem rather than a straightforward access-grant issue, since the same users were being treated inconsistently within the same share.

05 — Root Cause
A share-level and folder-level ACL mismatch

The root cause was a mismatch between share-level and folder-level permission inheritance — subfolder ACLs were not correctly inheriting from the parent share's permission set, producing the exact symptom seen: consistent access at the top, inconsistent access below it.

07 — Implementation
Backup architecture, plus a deliberate exposure decision
  • Implemented NAS-based backup with local and cloud replication as the recovery path for production data.
  • Corrected the share-level and folder-level ACL configuration so subfolder permissions correctly inherit from the parent share.
  • Separately, the VM hosted on the same NAS platform is made reachable through an outbound tunnel rather than any open inbound ports — see Security Considerations below.
08 — Security Considerations
Tunnel-based reachability over open ports

The VM hosted on the backup platform needed to be reachable for an internal service, without exposing the NAS to inbound connections from the internet. Rather than forwarding inbound ports — the more common but higher-exposure approach — it's made reachable through an outbound tunnel, so the platform holding the organization's backups never has an open inbound port as an attack surface.

09 — Validation
Backup success rate, not just job completion

Backup jobs were tracked for actual completion success rather than assumed from a scheduled-job status, reaching a near-100% success rate. The ACL fix was validated by confirming consistent access at both the share and subfolder level for the affected users.

10 — Result
35% faster recovery, near-100% success rate

The rearchitected backup approach reduced data recovery time by 35% compared to the prior approach, while maintaining a near-100% backup success rate.
